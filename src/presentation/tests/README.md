# Presentation sorting contracts

The track-sort and stable multi-key sorter suites live with the policy they exercise. They cover metadata/custom-tag keys, missing facts, stable identity fallback and ordering. Existing queue/repository fixtures use the explicit local resource adapter and the actual portable queue target. Neither test target links Qt or widgets.

The ordinary CMake targets are `presentation_track_sort_test` and `presentation_track_sorter_test`. Frontend model, selection, painting and journey tests remain with their bindings; those cases qualify behavior beyond these portable algorithms.
